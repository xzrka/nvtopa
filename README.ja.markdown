## このフォークが追加した機能

### 1. 幅適応型デバイスヘッダー

上流の nvtop はデバイスヘッダーを約 120 列の固定幅で配置するため、一般的なターミナルでは電力・ファン・クロックの各フィールドが右端で切れてしまいます。このフォークは、レイアウトを計算するより先にヘッダーをコンソール幅に合わせます。固定の**段階的諦め(give-up)ラダー**を順に下りながら、ファンの余白、クロックのラベル、ECC・NVLink フィールド、最後に最小/最大の表示を一つずつ手放し、行が収まるまで調整します。コア温度だけは決して完全には消しません。

```
Device 1 [NVIDIA GeForce RTX 3090] PCIe GEN 4@16x   NVL3 4x 0.000 KiB/s
1455MHz 9501MHz  TEMP  63° 46/66   JCT  74°C   VRAM  74°C   FAN  59%  POW 215 / 220 W
```

pty スイープテストにより、**40 列から 200 列まで**のどの幅でも何も切り取られないことを確認しています。

### 2. セッション最小/最大温度とリセットキー

`TEMP`・`JCT`・`VRAM` のそれぞれについて、現在の読み取り値に加え、プログラム起動時(または最後のリセット)以降に観測した最小値と最大値を表示します:

- `TEMP 63° 46/66` — 現在 63 °C、最小 46 °C、最大 66 °C
- **F7** で履歴をリセット。最小/最大値は現在の値に折りたたまれ、そこから再び追跡を始めます。

最小/最大値はターミナルのサイズ変更をまたいで保持されます。ターミナルウィンドウではなくデバイスの状態として保存されているためです。

### 3. PCIe の隣への NVLink スループット

NVLink の転送レートを、2 行目ヘッダーの末尾(狭いターミナルで最初に切れる位置)から**1 行目、PCIe スループットのすぐ隣**へ移しました:

```
Device 1 [NVIDIA GeForce RTX 3090] PCIe GEN 4@16x   NVL3 4x 0.000 KiB/s
```

PCIe フィールドのウィンドウ幅は、実際に描く形状に合わせて調整されます — 詳細形式 `PCIe GEN 4@16x RX: ... TX: ...`(46 列)、省略形式 `GEN 4@16x RX 9.2G/TX 10.1G`(30 列)、または `PCIe GEN 4@16x`(14 列)— そのため NVLink フィールドは空白の連続の後ろではなく、すぐ隣にぴったりと収まります。空間が完全になくなると(およそ 60 列未満)NVLink を諦め、PCIe に空間を返します。ブリッジのないボードは、以前と同様に空のスロットを保持します。

### 4. どの幅でも元のままの電力表示形式

上流は狭いターミナルで `POW x / y W`(現在/最大)を単なる `POW x W` へ落とします。このフォークはすべての幅で元の「現在/最大」形式を維持し、実際に譲るものがなくなったときだけフィールド自体を省略します。

### 5. GPU あたり最大 10 本のプロットライン

GPU ごとのチャートは一度に最大 10 項目の指標を受け付けます(上流は 4 項目)。既定では**デバイスごとに 1 つのチャートへすべてを表示**し、各ラインが固有の色を持ちます:

- GPU 使用率
- GPU メモリ使用率
- GPU コア温度
- メモリジャンクション(ホットスポット)温度
- メモリ(VRAM)温度

ボードが報告しないセンサーのラインは自動的に省かれます — RTX 3050 にはメモリ温度センサーがないため、`vram(c)` ラインは描画されません。

### 6. F8 — グラフ内容の切り替え

デバイスごとのチャートはモードによって異なる指標を表示し、**F8** がモードを巡回します。切り替え時にはプロットバッファを空にして、モード間でデータが混ざらないようにします:

| モード | 表示するライン |
| --- | --- |
| 全指標(既定) | 使用率、メモリ使用率、および報告されるすべての温度 |
| 元の nvtop | GPU 使用率とメモリ使用率のみ |
| 温度のみ | コア・ジャンクション・メモリ温度のみ |

### 7. GDDR レジスターから読むメモリジャンクション・VRAM 温度

このフォーク本来の機能で、[ThomasBaruzier/gddr6-core-junction-vram-temps](https://github.com/ThomasBaruzier/gddr6-core-junction-vram-temps) から移植しました:`JCT`(メモリジャンクション、ホットスポット)と `VRAM`(メモリデバイス)は、対応するどの API も報告しない GDDR6/GDDR6X/GDDR7 メモリコントローラーのレジスターから読み取ります。Ampere(RTX 30)以降の世代のみが対象で、それより古いボードには手を付けません。udev ルールで GPU の最初の BAR をグループに渡せば、一般ユーザーでも読み取れます — その設定を行うスクリプトは[マシン設定リポジトリ](https://github.com/xzrka/nvtopa-setup)にあります。

## キーボードショートカット

| キー | 動作 |
| --- | --- |
| `F2` | 対話型設定ウィンドウ(Chart ページでプロットラインと色を設定) |
| `F6` | プロセス一覧の並べ替え |
| `F7` | **温度履歴(最小/最大)のリセット** |
| `F8` | **グラフ内容の切り替え**(全指標 → 元の nvtop → 温度のみ) |
| `F9` | プロセスの終了 |
| `F10` | 終了 |
| `F12` | 設定の保存 |
| `Ctrl+L` | 全面再描画の強制 |

## テスト環境

このフォークは次の環境で開発・検証されています:

| 項目 | 内容 |
| --- | --- |
| GPU | NVIDIA GeForce RTX 3050 × 1(GDDR6、メモリ温度センサーなし)、NVIDIA GeForce RTX 3090 × 2(GDDR6X、NVL3 4x として NVLink 接続) |
| OS | Pop!_OS(Ubuntu 系)、Linux x86-64 |
| ドライバー | NVIDIA 専用ドライバー(NVML + BAR0 レジスターアクセス) |
| ターミナル | GNOME Terminal。pty ハーネスによるヘッドレス検証 |

検証方法:

- **`tests/temp_colors.py`** — プログラムを pty 内で再生し、各 `TEMP` / `JCT` / `VRAM` の数字に効いている SGR 色を抽出します。温度フィールドの色分けを自動で検査します。実行方法:`python3 tests/temp_colors.py 80 24 -- ./build/src/nvtop`
- **`tests/pty_capture.py`** — 任意サイズの pty でプログラムを実行し画面を出力します。40 列から 200 列までヘッダーをスイープし、各幅での段階的諦めラダーを検証するのに使われます。
- **`ctest`** — 上流のテスト群に加え、`nvidia_vram_temps`:センサーレジスターを偽の sysfs 上に用意し、デコード結果を検査します。
- **`tests/interfaceTests.cpp`** — PCIe 帯域幅テーブルのユニットテスト。
- **40・50・60・70・80・90・100・120・160・200 列**の手動 pty スイープにより、どの幅でも何も切れず、電力フィールドが常に `POW x / y W` 形式を保つことを確認。F8 の 3 つのグラフモードと F7 リセットは、pty と GNOME Terminal の実機の両方で試験しました。

## ビルドとインストール

標準的な nvtop のビルド:

```bash
git clone https://github.com/xzrka/nvtopa.git
cd nvtopa
mkdir build && cd build
cmake .. -DCMAKE_BUILD_TYPE=Release
make -j$(nproc)
```

このフォークを開発しているマシンでは、[マシン設定リポジトリ](https://github.com/xzrka/nvtopa-setup)の `install-nvtopa.sh` がフォークをビルドして `nvtopa` としてディストリビューションの `nvtop` の隣にインストールし、`unprivileged-temps.sh` が一般ユーザーでもメモリ温度レジスターを読めるようにする udev ルールを設定します。
